# Figure sources and display rendering

`../Figure_1.png` and `../Figure_1.pdf` are the 600 dpi raster and vector PDF assets for the current study overview. For Figure 1, the rendering entrypoint performs an asset export (`asset_export`) that copies those PNG and/or PDF bytes into the fresh output directory and records the export in the run receipt; it does not reconstruct the chemical drawings or workflow schematic from the scientific dataset, and the upstream Python layout script for Figure 1 has not been made portable here.

`Figure_1.svg` in this directory is retained as an earlier historical schematic. It is not the source of the current Figure 1 and is not read by `scripts/render_paper_figures.py`.

The numerical renderers read seven frozen display inputs under `data/figure_display/`, plus only the stored summary/layout fields they need. They retain the frozen numerical values, mathematical labels, guards and historical reference distinctions, but draw them in an earlier plotting layout: the panel arrangement, dimensions and annotations of the paper's Figures 3–6 and S1–S3 are not generated by this entrypoint. They do not read prediction files, train models or recalculate scientific scores.

From the repository root, in a Python 3.11 environment with `environments/figures.txt`:

```bash
python scripts/render_paper_figures.py
python scripts/render_paper_figures.py --figures 3,4,5,6,S1,S2,S3 --formats png,pdf,svg --output runs/my-new-figures
python scripts/render_paper_figures.py --figures 1 --formats png,pdf
```

The default figure set is `1,3,4,5,6,S1,S2,S3`. All outputs go to a fresh ignored `runs/figures_TIMESTAMP` directory. An explicit `--output` path must not exist and cannot overlap repository source or data. Existing output directories are never reused. Result-plot outputs are not a committed static figure gallery.

Figure 1 supports `png` and `pdf` through asset export:

- When a mixed format request includes `svg` alongside `png` or `pdf` (including the default `--formats png,pdf,svg`), Figure 1 exports the requested `png`/`pdf` files, skips `svg` with an explicit notice, and records its actual exported formats and paths in the run receipt, while numerical Figures 3–6 and S1–S3 continue to render `png`, `pdf` and `svg`.
- Requesting `--figures 1 --formats svg` alone exits with a non-zero status and reports that the current Figure 1 overview is available only as `png` and `pdf`.

For numerical figures, no browser executable or workstation font path is assumed. Arial is requested as in the retained plotting sources; if unavailable, DejaVu Sans is selected with an explicit warning and a receipt entry. Font metrics and SVG/PDF rendering can differ between platforms, so generated numerical-figure raster/vector bytes are not claimed to be identical to the publication files. Each run records its environment, font choice and outputs in `RENDERING_RECEIPT.json` in the output directory.

Figure 2 combines chemical examples and numerical graphics across panels A–C. Its scientific inputs remain in `data/identity/`, `data/folds/` and the saved diagnostics ([docs/FIGURE_2_SOURCES.md](../../docs/FIGURE_2_SOURCES.md)), but its complete portable historical production chain is not recovered by this entrypoint. Selecting figure 2 reports that limit; no replacement artwork is invented.
