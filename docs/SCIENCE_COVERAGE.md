## Historical execution boundaries

Three dated pointers refer to broader historical execution directories rather than missing scientific tables: the canonical fold builder, model-feature builder and fold-export wrapper. The public repository supplies the frozen folds, features, schemas, SHA bindings, scientific GNN core, configuration and saved outputs. It does not claim to reproduce historical run wrappers, unavailable upstream preparation inputs or internal logs.

The raw `records.parquet` is not redistributed. Its upstream location, byte count and SHA-256 are in `docs/DATA_SOURCES.md`. The public filter and two full-anchor diagnostic scripts accept that file explicitly.

The canonical GNN core creates complete host and guest graph batches and encodes them before selecting the requested pair rows (`scripts/canonical_gnn/scientific_core.py`, `_graph_batch` and `PairNetwork.forward`). Its three GINE `BatchNorm1d` layers therefore use nodes from held-out molecules during training-mode forward passes. This is a transductive representation channel even though held-out target labels are excluded from the loss; it is not a strictly inductive GINE comparison. The AttentiveFP wrapper and the recorded PyG 2.8.0 [AttentiveFP implementation](https://github.com/pyg-team/pytorch_geometric/blob/2.8.0/torch_geometric/nn/models/attentive_fp.py) contain no BatchNorm layers, so that specific BatchNorm limitation is not assigned to AttentiveFP or RF. Canonical graph early stopping uses a random 15% of training rows (at least 20), fixed seed 0 and one initialization per block, rather than a group-held-out inner validation design. These are results for the retained model configurations and protocol, not a model-class ranking. The separate later released GNN adapter likewise constructs complete graph batches and selects inner validation by randomly permuting training rows, using each released job's seed; it does not replace the canonical evidence or remove these design limits.
